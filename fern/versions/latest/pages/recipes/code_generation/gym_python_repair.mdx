This recipe generates deliberately broken CSV deduplicators with Kimi K3.1 Pro and checks that each starter reproduces its intended bug. A `gym-resource` column runs Pi with Nemotron 3.5 Lightning in a Gym-managed Docker sandbox. A second `gym-resource` column grades the exported repair in separate, network-disabled containers.

See [Collecting Agent Rollouts with NeMo Data Designer and Gym](/dev-notes/gym-rollouts) for a worked example and results from the 12-task experiment.

## Set up

Start Docker Desktop on macOS. Use [uv 0.13.4 or newer](https://docs.astral.sh/uv/getting-started/installation/) and export your [OpenRouter API key](https://openrouter.ai/settings/keys) as `OPENROUTER_API_KEY`. Leave local ports 18839-18841 free. OpenRouter serves both models and the workflow runs locally.

Start at the root of a [DataDesigner checkout](https://github.com/NVIDIA-NeMo/DataDesigner) that contains the recipe. Run both command blocks in the same shell so `RECIPE_DIR` and `GYM_RUNTIME` carry over.

```bash
cd docs/assets/recipes/code_generation/gym_python_repair
RECIPE_DIR="$PWD"
GYM_RUNTIME="$(mktemp -d)"
curl -fsSL https://codeload.github.com/NVIDIA-NeMo/Gym/tar.gz/1bc262ada7a419fdcf60f6b31d85cb717c939682 \
  | tar -xz -C "$GYM_RUNTIME" --strip-components=1
git -C "$GYM_RUNTIME" apply "$RECIPE_DIR/docker-desktop.patch"

uv venv --python 3.12 .venv-dd
uv pip install --python .venv-dd/bin/python 'data-designer==1.0.1' \
  'data-designer-gym @ git+https://github.com/NVIDIA-NeMo/DataDesignerPlugins.git@cd745a56c9ac99f7b8a5068be873474e9d75f82a#subdirectory=plugins/data-designer-gym'
uv venv --python '>=3.13.14,<3.14' "$GYM_RUNTIME/.venv"
uv pip install --python "$GYM_RUNTIME/.venv/bin/python" -e "$GYM_RUNTIME" requests tenacity jinja2
touch "$GYM_RUNTIME/.venv/.nemo-gym-setup-complete"
for component in responses_api_agents/pi_agent environment_servers/legacy_agent responses_api_models/openai_model; do
  ln -s "$GYM_RUNTIME/.venv" "$GYM_RUNTIME/$component/.venv"
done
```

The Docker Desktop patch lets Pi reach the host model proxy and uses a relative sandbox timeout on macOS. The Dockerfile pins Pi 1.5.2.

## Generate, repair, and verify

The recipe script has two commands. `generate` builds and qualifies starter tasks. `repair` runs them through Gym and executes `verify.py` in separate Docker containers. Use `--repeats 1` for a three-task smoke test, one starter per bug family. The default is four starters per family. Use a fresh run directory each time.

```bash
RUN="$RECIPE_DIR/.run-batch"
docker pull python:3.12-slim
docker build --tag dd-gym-poc-direct:pi-1.5.2 - < Dockerfile
.venv-dd/bin/python gym_python_repair.py generate "$RUN" --repeats 1
.venv-dd/bin/python gym_python_repair.py repair "$RUN" --gym-runtime "$GYM_RUNTIME" --concurrency 2
```

`repair` starts Gym's head server, Pi agent server, and model proxy from the prepared runtime and waits up to four minutes for Gym to start. It then starts the local service that handles Data Designer's `/repair` and `/verify` requests. The command stops these services when the batch ends. Check `$RUN/gym.log` if Gym fails to start.

## Inspect the results

- `stage1.jsonl` records the generated starter, public-test output, and qualification for each proposed row.
- `stage2.jsonl` records the rollout, verifier outcome, and `accepted` flag for each qualifying row. Acceptance requires a completed, unmasked verifier result with reward 1.
- `episodes/<row_id>/` holds the agent response, code diff, exported `clean.py`, and verifier evidence.
- `repair_run.json` records the batch counts and how many task containers remain after the run.
