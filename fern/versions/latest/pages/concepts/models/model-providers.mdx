Model providers are external services that host and serve models. Data Designer uses the `ModelProvider` class to configure connections to these services.

## Overview

A `ModelProvider` defines how Data Designer connects to a provider's API endpoint. When you create a `ModelConfig`, you reference a provider by name, and Data Designer uses that provider's settings to make API calls to the appropriate endpoint.

## ModelProvider Configuration

The `ModelProvider` class has the following fields:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | `str` | Yes | Unique identifier for the provider (e.g., `"nvidia"`, `"openai"`, `"openrouter"`) |
| `endpoint` | `str` | Yes | API endpoint URL (e.g., `"https://integrate.api.nvidia.com/v1"`) |
| `provider_type` | `str` | No | Provider type: `"openai"` (default) or `"anthropic"`. See [Supported Provider Types](#supported-provider-types) below |
| `api_key` | `str` | No | API key or environment variable name (e.g., `"NVIDIA_API_KEY"`) |
| `extra_body` | `dict[str, Any]` | No | Additional parameters to include in the request body of all API requests to the provider. Merged key by key over the model's and the call's `extra_body`, with provider keys taking precedence. See [Extra Body Precedence](/concepts/models/inference-parameters#extra-body-precedence). |
| `extra_headers` | `dict[str, str]` | No | Additional headers to include in all API requests to the provider. |

## Supported Provider Types

Data Designer supports two provider types:

| Type | Description |
|------|-------------|
| `"openai"` | OpenAI-compatible chat completion API. This is the default and works with most providers, including NVIDIA NIM, vLLM, TGI, OpenRouter, Together AI, and OpenAI itself. |
| `"anthropic"` | Anthropic's native Messages API for Claude models. Use this when connecting directly to Anthropic's API. |

Most self-hosted and third-party endpoints expose an OpenAI-compatible API, so `provider_type="openai"` is the right choice in the majority of cases. Only use `"anthropic"` when connecting directly to Anthropic's API at `https://api.anthropic.com`.

> **Note:** Previous versions of Data Designer supported additional provider types (e.g., `"azure"`, `"bedrock"`, `"vertex_ai"`) via a LiteLLM bridge. These are no longer supported. If you were using one of these types, switch to `provider_type="openai"` and point the `endpoint` to an OpenAI-compatible proxy or gateway for that service.

## OpenAI Responses API

Keep `provider_type="openai"` and set `ModelConfig.api="responses"` to route
normal generation and MCP calls to `/responses`. The default is `"chat-completions"`.
Models can share the same provider while selecting different APIs.

```python
from data_designer.config.models import ChatCompletionInferenceParams, ModelConfig, ModelProvider

provider = ModelProvider(
    name="openai",
    provider_type="openai",
    endpoint="https://api.openai.com/v1",
    api_key="OPENAI_API_KEY",
)
model = ModelConfig(
    alias="reasoning",
    model="gpt-5.6-luna",
    provider="openai",
    api="responses",
    inference_parameters=ChatCompletionInferenceParams(
        max_tokens=4096,
        extra_body={"reasoning": {"effort": "medium"}},
    ),
)
```

Use this provider and model in your `DataDesigner` and `DataDesignerConfigBuilder`
configuration. Text, code, judge, image-context, and MCP columns use the selected
route in both sync and async generation. The `api` option applies only to
chat-completion inference parameters.

`max_tokens` maps to `max_output_tokens`. `reasoning_effort` in `extra_body` also
maps to `reasoning.effort`; specify only one form. Structured outputs map to
`text.format`. Model-specific sampling restrictions still apply.

Requests use `store=false` and include `reasoning.encrypted_content`. DD replays
ordered output items, including encrypted reasoning and function calls, on every
MCP round. Direct `ModelFacade.responses()` / `aresponses()` callers can carry
`response.message.replay_data` into the next assistant `ChatMessage` using its
`replay_data` field. Keep the original conversation and tool results in order,
following [OpenAI conversation-state guidance](https://developers.openai.com/api/docs/guides/conversation-state).

`responses()` / `aresponses()` explicitly select the provider's conversation API,
regardless of the model's `api` setting. `completion()` / `acompletion()` retain
the existing API. For Anthropic, the conversation API is its native Messages API
and replay data preserves thinking blocks and signatures.

```python
from data_designer.engine.models.utils import ChatMessage

# model is a ModelFacade returned by DataDesigner.get_models().
history = [ChatMessage.as_user("First question")]
response = await model.aresponses(history)
history.append(ChatMessage.as_assistant(
    content=response.message.content or "",
    replay_data=response.message.replay_data,
))
history.append(ChatMessage.as_user("Follow-up question"))
response = await model.aresponses(history)
```

The adapter rejects streaming, background execution, server-stored conversations,
multiple choices, stop sequences, seed, frequency/presence penalties, and hosted
tools. It supports DD-managed function tools. Configure an Azure OpenAI v1 base
endpoint and its required authentication headers explicitly; legacy deployment
URLs, API-version query parameters, and automatic Azure credential refresh are
not handled by this adapter.

## API Key Configuration

The `api_key` field can be specified in two ways:

1. **Environment variable name** (recommended): Set `api_key` to the name of an environment variable (e.g., `"NVIDIA_API_KEY"`). Data Designer will automatically resolve it at runtime.

2. **Plain-text value**: Set `api_key` to the actual API key string. This is less secure and not recommended for production use.

```python
# Method 1: Environment variable (recommended)
provider = ModelProvider(
    name="nvidia",
    endpoint="https://integrate.api.nvidia.com/v1",
    api_key="NVIDIA_API_KEY",  # Will be resolved from environment
)

# Method 2: Direct value (not recommended)
provider = ModelProvider(
    name="nvidia",
    endpoint="https://integrate.api.nvidia.com/v1",
    api_key="nvapi-abc123...",  # Direct API key
)
```
